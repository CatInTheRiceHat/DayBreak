# Documentation

Project documents are grouped by purpose so new work has an obvious home:

- `architecture/` — technical explanations and system design
- `design/` — visual direction and style guides
- `operations/` — deployment and maintenance runbooks
- `plans/` — approved implementation plans
- `specs/` — feature and product specifications
- `research/` — research papers, matrices, and source material
- `reports/` — completed reviews, audits, and their supporting evidence

Keep the root `README.md` focused on setup and navigation. Put dated proposals in
`plans/` or `specs/`; put post-build findings in `reports/`.
